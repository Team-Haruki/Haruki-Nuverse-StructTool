# AGENTS.md

Guidance for coding agents and contributors working in this repository. This file is the single source of truth; `CLAUDE.md` only points here.

## Purpose

Restores and re-encodes the compact (stripped) MessagePack payloads used by the Nuverse regions of Project Sekai. Payloads are decoded against custom-Avro-style schemas whose fields carry a `msgpack_key` (array index or map key), and in Go and Python the same schemas drive encoding back to compact msgpack.

The parser is implemented in three languages: Go (the primary CLI and library) and Python implement decode and encode; the Rust port implements decode only (its `encode` returns an error).

## Layout

| Path | What it is |
| --- | --- |
| `main.go`, `main_test.go` | Go CLI (`package main`): `--schema`, `--class`, then `--hex` (decode) or `--json` (encode); `-v` enables debug logging |
| `avro_parser/` | Go library: `LoadFile`, `LoadBytes`, `Decode`, `Encode`, `Registry`, `Schema` |
| `python/avro_parser/` | Python package (`haruki-nuverse-structtool`, `requires-python >=3.10`, depends on `msgpack`); exports `LoadFile`, `LoadBytes`, `Decode`, `Encode`, `Registry`, `Schema` |
| `python/tests/` | Python `unittest` tests |
| `rust/avro_parser/` | Standalone Cargo project (not a workspace): library `avro_parser` (`load_file`, `load_bytes`, `decode`; `encode` is a stub that always returns an error) and a decode-only binary (`--schema`, `--class`, `--hex`) |
| `data/master.avsc` | Generated `Sekai.Master*` schemas (CDN `master-data-<cdnVersion>.info` payloads) |
| `data/suite.avsc` | Generated `Sekai.SuiteUser` / `Sekai.User*` schemas (suite, profile, ranking payloads) |
| `sonar-project.properties` | SonarQube Cloud project settings |

## Build, run, test

Go (version from `go.mod`):

```bash
go build
go run . --schema data/master.avsc --class Sekai.MasterActionSet --hex 9B0104A46E6F6E65C2C0AD61735F636473686F705F6D6F62C09101C0CF00000157B64DF001C0
go run . --schema data/master.avsc --class Sekai.MasterActionSet --json '{"id":1}'
go test -race ./...
gofmt -l . && go vet ./...
```

Python (uv, run from `python/`):

```bash
uv sync --locked --group test
uv run python -m unittest discover -s tests
```

Rust (run from `rust/avro_parser/`):

```bash
cargo fmt --check
cargo clippy --all-targets -- -D warnings
cargo test
cargo run -- --schema ../../data/master.avsc --class Sekai.MasterActionSet --hex <hex>
```

## Schema assets

- `data/master.avsc` and `data/suite.avsc` are generated by `tools/nuverse_schema_generator` in Team-Haruki/Haruki-Sekai-API from DummyDll metadata (`Assembly-CSharp.dll`, `MessagePackObject` / `Key` attributes) and copied here. Regenerate them there; do not hand-edit them.
- Field names are restored JSON names (camelCase, leading backing underscores removed); `msgpack_key` keeps the original key. Raw upstream exporter output must go through the Haruki normalization step before it replaces these files.
- `.gitignore` ignores `*.avsc` and `*.json` except the two committed schema files; a new schema file under `data/` needs its own `!` exception.

## Behaviour notes

- Records decode from a msgpack array (int `msgpack_key` = array index) or a map (string or stringified int key). Records with `msgpack_unions` are `[discriminator, payload]` pairs and decode to `{"__type": <int>, "value": <payload>}`.
- Map-format records keep unknown keys in the output under their raw key; array-format records drop indices that have no schema field.
- msgpack nil decodes to `null` even for non-nullable schema types.
- The Go CLI writes its logs to stdout along with the result. In `--hex` mode it re-encodes the decoded value and logs whether the round trip matched only at debug level (`-v`).
- Running Python from the repository root needs the package installed (`pip install -e python/`) or `PYTHONPATH=python`; otherwise the Go `avro_parser/` directory shadows it as an empty namespace package.
- Keep the implementations in step: a decoding fix in one language usually belongs in the other two, with tests; an encoding fix applies to Go and Python only.

## CI

`.github/workflows/ci.yml` runs on pushes and PRs to `main` (plus manual dispatch) using the shared `seiunx-dev/ci-templates` reusable workflows `@v1`:

- **Go**: gofmt, go vet, staticcheck, `go mod tidy -diff`, build, `go test -race` with coverage.
- **Rust** (`rust/avro_parser`): `cargo fmt --check`, clippy with `-D warnings`, `cargo test`.
- **Python** (`python`): `uv sync --locked --group test`, unittest under coverage, then a decode smoke test of `Sekai.MasterActionSet` against `../data/master.avsc`. Ruff is disabled until the package is cleaned up.
- **Sonar**: SonarQube Cloud scan using the Go and Python coverage.
- **Workflow lint**: actionlint.
- **CI OK** aggregates all jobs and fails if any of them failed or was cancelled; it is the job intended as the required check (`main` currently has no branch protection or ruleset).

There is no release workflow or tagged release; consumers use the code and schema files from `main`.

Dependabot (`.github/dependabot.yml`) opens weekly grouped updates for gomod, cargo, uv and GitHub Actions with the `[Chore] ` prefix.

## Conventions

- Commit and PR titles use a bracketed type prefix: `[Feat]`, `[Fix]`, `[Docs]`, `[Chore]`, `[CI]`, followed by an imperative summary.
- Recent changes (including Dependabot updates) land on `main` through PRs; "CI OK" should be green before merging.
- Documentation is in English.
